Local receive-only training stack

Set up the tools that feed live signals into the CTF.

This page is the developer route from a fresh machine to a live GNU Radio flowgraph driving the Signal Forge waterfall. The assessed range still works without SDR hardware; GNU Radio and ZMQ are for building better captures, stronger subtasks, and live demonstrations.

Default live path GNU Radio -> ZMQ PUSH -> Python bridge -> Signal Forge ingest -> External feed
1. Run the site 2. Python tools 3. GNU Radio 4. External feed 5. ZMQ bridge 6. Flowgraph pattern 7. Verify 8. Research path

Step 1

Run the CTF Server

Start the local Python server first. It serves the pages, validates flags, parses raw IQ, and opens the local signal-ingest socket. 

cd C:\GithubRepositories\COMP6841\Project_SomethingAwesome\Project
$env:PORT='8002'
python server.py
Website
http://localhost:8002
Signal ingest
127.0.0.1:9100
Browser mode
Open a challenge and select External feed.

Step 2

Install Python Tooling

The base CTF uses only the Python standard library. The ZMQ bridge needs `pyzmq` in the environment where the bridge runs. 

python -m pip install pyzmq

On Ubuntu or WSL, the distro package is usually enough:

sudo apt update
sudo apt install python3-zmq

Step 3

Install GNU Radio

On Windows, use WSL/Ubuntu for the smoothest GNU Radio Companion workflow. Keep flowgraphs receive-only or file/generated for this project. 

wsl --install
sudo apt update
sudo apt install gnuradio python3-numpy python3-scipy python3-zmq
gnuradio-companion

If WSL graphics are not working, generate `.py` flowgraphs or file sinks in WSL and inspect the output through the website on Windows.

Step 4

Test the External Feed

Before wiring GNU Radio, prove the browser path works with the included sender. This should make the waterfall update immediately after the challenge page is switched to External feed. 

python tools/script_clients/external_signal_sender.py --challenge-id tunnel-packet-injection --mode fft

Raw IQ test:

python tools/script_clients/external_signal_sender.py --challenge-id tunnel-packet-injection --mode iq --block-samples 2048

Stream an existing GNU Radio file sink output:

python tools/script_clients/external_signal_sender.py --challenge-id tunnel-basic-dos --mode file --file radio/GNURadio/Tunnel_Task/DoSAttackMe.sigmf-data --loop

Step 5

Bridge GNU Radio over ZMQ

Use a GNU Radio ZMQ sink for live work. The bridge receives raw GNU Radio messages and forwards them into the same ingest socket used by the External feed button. 

python tools/script_clients/zmq_signal_bridge.py --challenge-id tunnel-packet-injection --endpoint tcp://127.0.0.1:5555 --pattern pull --dtype cf32 --center-hz 915000000 --sample-rate-hz 44200 --span-hz 44200

PUSH/PULL

Best default when the website bridge is the only consumer.

GNU Radio ZMQ PUSH Sink -> bridge --pattern pull

PUB/SUB

Useful when several tools need the same stream.

GNU Radio ZMQ PUB Sink -> bridge --pattern sub

Step 7

Verify the Pipeline

  1. The server prints that Signal Forge is serving on `localhost:8002`.
  2. The server status endpoint reports ingest enabled on `127.0.0.1:9100`.
  3. The bridge prints ZMQ connection status and forwards frames.
  4. The challenge workbench shows External feed metadata.
  5. The waterfall moves continuously and the parser panel updates.
Invoke-WebRequest -UseBasicParsing 'http://localhost:8002/api/rf/external/status?challenge_id=tunnel-packet-injection'

Where to Push the Project Further

Signal design

Add distinct schemes per situation: OOK signage, FSK tolling, AM voice, weak PRNG hopping, DSSS, deceptive replay, and protocol-aware jamming.

RF realism

Model SNR, fading, Doppler, capture effect, receiver saturation, AGC behaviour, adjacent-channel interference, and timing recovery.

Cyber depth

Pair RF-derived inputs with firmware reversing, native parser bugs, fuzz harnesses, signed packet checks, authorization logic, and backend telemetry correlation.

Defence

Build Secure Mode around freshness, message authentication, server-side policy, hardened parsers, anomaly detection, and operational holdover logic.
