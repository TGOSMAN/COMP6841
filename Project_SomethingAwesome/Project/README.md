# Signal Forge CTF

Signal Forge is a sim-first contested-spectrum operator CTF about a synthetic roadside access point and its smart-tolling services. It combines RF acquisition with seven concrete operator tests:

1. Acquire an RSU access point and recover receiver output.
2. Receive and decode an operator telemetry frame.
3. Pivot from recovered user data into the local toll API.
4. Inject a replay waveform that produces a zero-price toll.
5. Transmit a malformed TLV that reaches RSU diagnostic mode.
6. Decipher a randomized UHF AM voice protocol and inject a synthetic emergency message.

All RF artifacts use 1024 FFT bins. The Python backend derives flags from a random server secret, the browser session, and the challenge ID. Two browser sessions therefore receive different valid flags. Flags appear only in successful receiver, target, service, effects, or console output.

The CTF is designed to run without SDR hardware. GNU Radio is the live DSP
runtime for mapped flowgraph challenges; it does not transmit over the air.

## Run Locally

Create a virtual environment, install the repository requirements, and use the
Python backend rather than a static file server:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python server.py
```

On Linux/macOS, activate the environment with `source .venv/bin/activate`.

Then open:

```text
http://localhost:8000
```

Each challenge also has a bookmarkable workspace at:

```text
http://localhost:8000/challenge/<challenge-id>
```

The workspace is self-contained. It combines a streaming waterfall, Basic and Advanced RX controls, a local-only TX chain, target artifacts, session flag submission, and an RF command terminal backed by `server.py`. The analyser supports centre/span tuning, gain, squelch, demodulation, 1024-bin FFT display, noise-floor and dynamic-range controls, colour palettes, 15/30/60 fps playback, a frequency ruler, cursor callouts, and a spectrum trace. Transmitted waveforms appear in magenta on the live waterfall.

Type `help` in the range terminal for an overview, or use `help rx`, `help tx`, `help request`, `help effects`, and `help mission` for detailed command pages.

The server initializes `data/tolling.db` on startup and serves both the webpage and JSON APIs.
The web server itself starts even when GNU Radio is not installed. A mapped RF
challenge never substitutes saved samples or a synthetic fallback: its analyser
shows a prominent **No live signal data received** message until the generated
GNU Radio Python flowgraph is running and streaming CF32 samples.

## Project Structure

- `index.html`, `styles.css`, `app.js` - browser CTF interface.
- `server.py` - dependency-free Python HTTP API and static server.
- `config/range.json` - editable RF, telemetry, and security settings.
- `data/challenges.json` - editable public challenge intelligence and artifacts; session flags are generated by the Python backend.
- `captures/` - legacy/reference RF analysis material; it is not used as a runtime signal source.
- `artifacts/` - cyber challenge inputs such as telemetry frames.
- `tools/` - local RE and parser challenge sources/harnesses.
- `docs/gnu-radio-workflow.md` - GNU Radio development path.

## Developing More Challenges

Add or edit challenges in `data/challenges.json`. Each challenge supports:

- `id`, `title`, `track`, `difficulty`, `points`
- `scenario`, `objective`, `concepts`
- `signal_scheme` for the unique RF/protocol scheme attached to that task
- ordered `steps`
- downloadable `artifacts`
- hint ladder
- an RF target definition and server-side success condition for dynamic session flags

For new GNU Radio RF tasks, commit the `.grc` source and its generated `.py`
flowgraph, connect the post-channel-model output to `SignalForgeLiveSink`, and
map that Python file in `server.py`. Do not add a File Source, WAV source, File
Sink, SigMF sink, recorded IQ replay, or browser-capture fallback.

For new cyber tasks, add local-only artifacts under `artifacts/` or `tools/`, then link them from the challenge JSON.

## GNU Radio Direction

Recommended workflow on Windows is WSL/Ubuntu:

```bash
sudo apt update
sudo apt install gnuradio python3-numpy python3-scipy
gnuradio-companion
```

Use GNU Radio Companion to generate the Python flowgraphs. The mapped
flowgraphs include a Signal Forge sink connected after the channel model. Start
the site normally with `python server.py`; when a mapped challenge opens, the
server discovers a GNU Radio-capable Python runtime and launches the exact
generated Python flowgraph from its own folder. Its CF32 stream is sent to
`127.0.0.1:9100` and consumed by the normal **Live parser** view.

Runtime discovery checks the active Python environment, `PATH`, Radioconda, and
common Conda environment locations on Windows, Linux, and macOS. For a custom
installation, set the interpreter explicitly before starting the server:

```powershell
$env:SIGNAL_FORGE_GNURADIO_PYTHON="C:\path\to\gnuradio\python.exe"
python server.py
```

```bash
SIGNAL_FORGE_GNURADIO_PYTHON=/path/to/gnuradio/bin/python python3 server.py
```

If discovery or flowgraph startup fails, the challenge reports that failure in
the analyser. It intentionally does not read a WAV, SigMF, capture JSON, or raw
IQ file and does not start a backend-generated replacement signal.

See `docs/gnu-radio-workflow.md` for the detailed path.

## Security Notes

The `/api/toll/events` endpoint is intentionally vulnerable so players can learn SQL injection safely in a local training environment. The `/api/toll/safe-events` endpoint demonstrates the defensive version using parameterized queries.

Do not copy the vulnerable query pattern into production code.

The defensive examples demonstrate several state-of-practice controls at training scale:

- HMAC over telemetry fields.
- Timestamp freshness.
- Nonce replay rejection.
- Parameterized SQL.
- Server-side schedule authorization.
- Output encoding / safe DOM rendering for operator comments.
- Bounded parser design in the safe C source.
- Firmware signing, measured boot, protected key storage, and attestation as advanced design requirements.
- RF/cyber detection fusion for jamming, replay, and suspicious-but-valid telemetry.
